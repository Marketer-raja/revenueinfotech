# Free editorial automation

1. Back up your repository. Extract this ZIP and copy the contents of revenueinfotech-main into your existing repository root, including the hidden .github directory. Do not delete your own credentials or domain configuration.
2. Use a PUBLIC GitHub repository if its contents are suitable for public access. This workflow deliberately skips private repositories to avoid paid runner usage. Never commit secrets. Standard hosted runners on public repositories are currently free, subject to GitHub terms and availability. Existing domain/hosting charges are separate.
3. Settings > Actions > General: allow Actions and read/write workflow permissions. Actions > RevenueInfoTech editorial publishing > Run workflow. No OpenAI key is needed. The workflow installs Ollama and downloads Qwen2.5:3b, generates up to three drafts per run, every six hours. Pushes to approved content files rebuild pages without running AI. Scheduled publication runs on the six-hour cadence, not exact minute. GitHub schedules may be delayed.
4. Open /newsdesk/ and connect the repository using a fine-grained GitHub token with Contents read/write, limited to this repository. Do not share the token. Avoid the remember option on shared computers. Prepared drafts load automatically; Refresh prepared articles reloads. Open prepared draft fills the editor, including image and suggested research links. Read the original source pages, verify every factual claim, remove unrelated sources, add independent context where needed, and confirm editorial responsibility. Approve and add to list, then Publish to site, or schedule for later.
5. If GitHub Actions errors, inspect logs. For local operation install Ollama from https://ollama.com, run `ollama pull qwen2.5:3b`, then from repo root run `python scripts/fetch_news.py`, `python scripts/prepare_drafts.py`, `python scripts/publish_scheduled.py`, `python scripts/build_articles.py`; commit changes yourself. Local computer electricity/internet costs may apply.

## Quality and limitations
- RSS headline discovery only, no full-text scraping or publisher image reuse. Related headlines are heuristic research leads, not confirmed corroboration. The model cannot verify facts or read source pages. It may produce inaccurate or generic text. It rejects malformed, too-short or visibly copied drafts; no copyright guarantee. Some leads stay in research-needed state. Review all drafts before approving.
- Original SVG illustrations are generated by code, not actual news photos. The archive has not been copyright-audited. Existing content should be checked before AdSense application.
- Drafts and source metadata in news.json are publicly accessible on static hosting and public GitHub. They are not intended for confidential material and are excluded from article generation until approved. Do not enter personal/private notes. No paid APIs or subscriptions are required by this code. Free service limits and policies may change.
- Google publisher policy: https://support.google.com/publisherpolicies/answer/11190248 ; GitHub billing: https://docs.github.com/en/actions/concepts/billing-and-usage
- This ZIP is not deployed. Live feed access, model installation and actual AI generation need to be tested in your repository. AdSense approval is not guaranteed.

## Mobile publishing update (supersedes earlier six-hour publishing instructions)
Open https://revenueinfotech.com/newsdesk/ on your own phone, sign in with repository owner/name/branch and a repository-limited fine-grained token with Contents read/write. Prefer session-only access; log out when finished. Add the page to your home screen via your browser if desired. Open a prepared draft, verify it, then tap Approve & publish (10-minute queue). Leave optional date blank for next eligible cycle. Refresh queue to view waiting stories. Existing article edits are saved separately. Each publisher run releases at most ten approved articles, with at least ten minutes between recorded releases. The free GitHub scheduler is best-effort, not a guaranteed exact timer; shared concurrency, model runs, push conflicts and deployment delays may postpone a release. The publisher checks every ten minutes on the default branch, and can also be run manually. News generation stays at six-hour intervals, with up to ten draft attempts per run. Select reviewed drafts and use Approve selected (up to 10). This is not a guarantee of ten new drafts every ten minutes. A public repository is required by these workflows. Hosting must rebuild on bot commits (e.g. configured Cloudflare Pages/Netlify Git integration); GitHub Pages branch deployment may not trigger from GITHUB_TOKEN commits and requires a separate Pages deployment workflow. The phone does not need to stay online after approval. No phone or hosting connection has been tested. Never commit tokens or share them in chat.
