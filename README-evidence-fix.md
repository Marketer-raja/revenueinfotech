# Evidence screening fix
Apply on top of the End-to-End Upgrade, not instead of it. Replace scripts/research_news.py, scripts/prepare_drafts.py and .github/workflows/update-news.yml. Optional test: tests/test_evidence_screen.py.

The previous 65-word gate was applied both to direct lead admission and drafting eligibility. This patch lowers the screening threshold to 40 words, not the final article quality requirement. A model must still decline when facts are insufficient; original title, summary, verification notes and a body of at least 120 words and 600 characters are required. The log now distinguishes raw matches, evidence rejected for length, direct leads and eligible matches. A new draft_limit input defaults to 1 and clamps attempts to 1–10.

If no eligible matches remain, examine Research word lengths. Where the publisher's terms permit automated processing of extended RSS content, edit that publisher's existing research-feeds.json entry to set allow_extended to true. Do not enable this indiscriminately. No raw feed excerpts should be published. Do not bypass access controls or paywalls. If sources still lack enough facts, keep those leads unapproved.

Run editorial publishing with draft_limit=1 and allow_private=true only within your available hosted runner allowance. If a draft passes, run Telegram news review with test_only=false and allow_private=true, review the actual article and press Approve, then run Telegram news review again to process the callback and publish. Website deployment must be checked separately. Existing Telegram scripts, secrets and schedules are unchanged. Private scheduled runs remain disabled unless a self-hosted runner is configured. No guarantee of live AI success, a fixed volume, zero infrastructure costs or AdSense approval.
