# RevenueInfoTech editorial quality upgrade

Replace the seven Python files under scripts/, research-feeds.json and .github/workflows/update-news.yml. Optional test: tests/test_quality_upgrade.py. Based on the previous End-to-End, Evidence Screen, Draft Retry and Approval Diagnostics packages, not a live private repository checkout. Back up or commit your current files first. Merge customized feed settings rather than overwriting them. Do not replace news.json, home-news.json, scheduled-news.json, telegram-state.json or Telegram publishing files.

## Research settings
The evidence minimum is now 80 words (previously 40); the article minimum remains 120 words/600 characters, with 300–600 words a target only when justified. Longer existing feed summaries are retained in memory. Additional suggested feeds are disabled until you confirm the publisher's terms permit automated processing and your intended commercial use. Verify the feed URLs before enabling. Set allow_extended=true only where you have permission to process extended feed content. Do not copy source prose or images into the published article. A source link alone is not a licence. A richer source is more valuable than padding. If no eligible evidence exists, the system will report zero drafts; the patch deliberately does not force output.

## Editorial workflow
The writer produces the existing JSON draft schema; a separate AI review compares claims to evidence. A heuristic quality score must reach 85. This is not independent verification or a Google metric. Missing review or unsupported claims block the draft. A bounded repair includes the actual prior draft and issue. Existing pending drafts are retained. New metadata is advisory only, not a change to rendered HTML or sitemap. Existing original category SVG illustrations remain. No live image generation is added. The local model has a separate per-run budget. The 420-second drafting budget is a soft limit checked between stories; a call can overrun it. The existing 20-minute job timeout still applies. No paid provider is automatically enabled. Review provider free plan settings and GitHub usage.

## Test
Run editorial publishing with draft_limit=1 and allow_private checked only if you have sufficient free runner allowance. Look for Editorial quality score, Draft prepared, and Queue totals. Review actual facts and image rights in Newsdesk. Run Telegram news review with test_only=false, resend_review=false unless intentionally refreshing an old batch, and allow_private as appropriate. Approve the new reviewed draft and run Telegram review again for manual testing. Verify the live site after hosting deployment. Increase to 10 only after successful tests. Existing schedule is every ten minutes when NEWS_AUTO_GENERATE=yes and repository runner conditions permit. Private scheduled automation requires the configured Linux self-hosted runner; do not set NEWS_PRIVATE_SELF_HOSTED=yes until the runner exists. Existing Telegram schedule also depends on runner conditions. GitHub schedules can be delayed; ten articles every ten minutes is not guaranteed. No promise of AdSense approval.

Local test command from repo root: python -m unittest discover -s tests -p test_quality_upgrade.py . The eight tests use mocked AI responses, not live credentials. Existing older tests may require fixture updates for the new evidence threshold and review stage.
