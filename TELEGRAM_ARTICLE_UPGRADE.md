# RevenueInfoTech: article research, Telegram review and publishing upgrade

## Install (patch only)

Back up your current repository. Merge the contents of `scripts/` and `.github/workflows/` into the corresponding existing directories on `main`. Upload `research-feeds.json` to the repository root (merge any custom feed entries rather than deleting them). The test file is optional for production. Do not replace `news.json`, `home-news.json`, `scheduled-news.json`, `telegram-state.json`, the site design or existing secrets. The patch was built against the earlier supplied hybrid ZIP plus research and Telegram patches, not a live checkout of your private repository.

## Safe initial test

1. In Settings → Secrets and variables → Actions → Variables, set `GROQ_FREE_CONFIRMED=no`, `MISTRAL_FREE_CONFIRMED=no`, `OPENROUTER_FREE_CONFIRMED=yes` only if its free-only credentials are confirmed, and `GEMINI_FREE_CONFIRMED=yes` only if its account remains free-only. Leave the secrets in place. No new secrets needed. Keep `NEWS_AUTO_GENERATE` and `NEWS_PRIVATE_SELF_HOSTED` unset for the initial test.
2. Actions → RevenueInfoTech editorial publishing → Run workflow. Branch main; `draft_limit=1` (or 3 if testing more); select `allow_private` only if you have verified sufficient included GitHub-hosted runner allowance and configured billing to prevent spending. Read Prepare editorial drafts. Look for Draft prepared and Queue totals. If no ready drafts, examine individual rejection reasons. No data is manufactured merely to fill a queue.
3. Actions → Telegram news review → Run workflow. Uncheck `test_only` and enable `allow_private` only under the same billing conditions. The bot sends full text, summary, source and illustration links, and review notes, followed by a batch approval button. No complete drafts means no notification. Review facts and source rights before approving. The button approves the exact unchanged batch, not edits made later in Newsdesk.
4. Tap Approve in Telegram. Run Telegram news review once more with test mode disabled, if automatic scheduling isn't enabled. The same run now processes approvals, releases up to 10 eligible approved articles, rebuilds pages and sitemap, commits updates and sends a confirmation after the commit. The 10-minute publishing cooldown is retained. Verify your website after your hosting provider deploys the commit. GitHub Actions commits using GITHUB_TOKEN do not trigger all other GitHub workflows or GitHub Pages builds, so check your actual deployment integration if the live website does not update.

## Automatic scheduling without paid cloud runners

Public repositories can use standard hosted runners subject to GitHub terms; do not make a private repository public without inspecting confidential files and drafts. For a private repository, automatic hosted generation/Telegram/publishing remains blocked by default. Manual hosted runs require explicit allow_private. For automatic runs on a private repository, configure a trusted Linux self-hosted runner (e.g. Linux/WSL on your PC), install Python 3, Git, curl and Ollama with qwen2.5:3b, register it to this private repository via Settings → Actions → Runners → New self-hosted runner, add the custom label `revenueinfotech`, and start the runner. Keep the machine running and restrict access to trusted code. Only then set repository variable `NEWS_PRIVATE_SELF_HOSTED=yes`. To opt into scheduled article generation set `NEWS_AUTO_GENERATE=yes`. Do not activate the old n8n schedule in addition to GitHub scheduling. If a public repository is used, never expose secrets or run untrusted PR code on self-hosted machines. Scheduling is best-effort, and jobs sharing the concurrency group can delay or replace pending runs. Free provider quotas, network availability and local hardware limit actual volume. No guarantee of ten articles every ten minutes. Electricity/hosting/domain costs are separate. Leave optional paid billing disabled.

## Research and editorial safeguards

Original six discovery sources are retained. The research stage can also add direct, recent leads from the previously configured research feeds when there is useful supporting material. RSS summaries can be processed temporarily; extended feed content is opt-in per feed via `allow_extended`, only when you have verified permission for automated processing. Disable sources whose terms prohibit your use. The code does not bypass paywalls or scrape full publisher pages. Summary evidence below 65 words is skipped, and models can still decline. Reports target 160–300 words (minimum 120 words and 600 characters) with attribution and conditional analysis; the minimum is an editorial choice, not an AdSense rule. Keep the existing originality checks and human review. The code checks format and copying heuristically, not factual truth. A generated SVG is an editorial illustration, not a news photograph. There is one bounded repair pass for format/originality failures within provider call caps. Mistral and Groq can be re-enabled only after confirming access and free-only status. No guarantee of copyright compliance or AdSense approval. Review publication rights and facts before approving.

## Tests

From repository root: `python3 -m unittest discover -s tests -v`. The new integration test uses fictional source data and mocked AI/Telegram API responses to verify draft creation, illustration, authorized approval, duplicate protection, queue release and page/sitemap build. It does not make real API requests or deploy anything. No live keys or production publishing were tested here.
